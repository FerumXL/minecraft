# Сборка и автотесты

## Что нужно

- Windows, JDK 8. На машине разработчика это 32-битная OpenJDK 8; переменная `JAVA_HOME` должна указывать на JDK 8.
- ForgeGradle 1.2, Forge `1.7.10-10.13.4.1614`. Кэш Gradle должен быть уже заполнен, команды ниже идут с `--offline`.
- Закрытая игра. При запущенной игре сборке на 32-битной JDK не хватает памяти.

## Сборка

Сначала восстанови файлы Mojang, которых нет в репозитории (984 файла: JSON достижений и рецептов, часть текстур):

```bat
python tools/fetch-assets.py
```

По умолчанию берётся `%APPDATA%\.minecraft`, другой путь можно передать аргументом. Нужен установленный 1.12.2 (`versions/1.12.2/1.12.2.jar`). Без этого шага сборка пройдёт, но в моде не будет достижений, книги рецептов и части текстур.


```bat
gradlew.bat build --offline -q
```

Для игры нужен `build/release/mc112bridge-<версия>.jar`, а не `build/libs`. Для установки положи его в `.minecraft/mods` и убери предыдущую версию.

С версии 0.24.0 мод содержит coremod (`asm/Plugin`, `asm/Transformer`). В манифесте jar указаны `FMLCorePlugin` и `FMLCorePluginContainsFMLMod`, а `runClient` запускается с `-Dfml.coreMods.load=...` из `build.gradle`.

## Запуск автотестов

Автотест встроен в клиент и включается только переменной окружения `MC112_AUDIT`. Без неё он ничего не делает.

```powershell
$env:JAVA_TOOL_OPTIONS = '-XX:TieredStopAtLevel=1 -XX:ReservedCodeCacheSize=64m'
$env:MC112_AUDIT = 'new'
.\gradlew.bat runClient --offline -q
```

`JAVA_TOOL_OPTIONS` нужны для 32-битной JDK: без них JVM падает с нехваткой нативной памяти при компиляции (C2).

| `MC112_AUDIT` | Что делает | Мир | Результат |
|---|---|---|---|
| `new` | Регистрации, галерея всех блоков, спавн всех сущностей, функциональные проверки, генерация в трёх измерениях, скриншоты, сохранение | `audit112`, обычный | `run/audit112-new.txt`, `run/audit112-dump.tsv`, `run/screenshots/audit-*.png` |
| `reload` | Загружает мир после `new`, сверяет блоки, инвентари, сущности | `audit112` | `run/audit112-reload.txt` |
| `more` | Сценарии на клиенте: слизь, облако, стрелы, бутылка, окно командного блока, клавиша L, панель книги, губка, левитация, звуки, лут, удача, ванильные механизмы, ходьба | `audit112m`, плоский | `run/audit112-more.txt` |
| `more2` | Загружает мир после `more`, проверяет карту с меткой | `audit112m` | `run/audit112-more2.txt` |
| `scene` | Постановочные скриншоты для сравнения с 1.12.2 | `audit112m` | `run/screenshots/s-*.png` |
| `bench` | Замер FPS и средней длительности тика на мире `audit112` | `audit112` | `run/audit112-bench.txt` |

Строки результата: `PASS <имя> ...`, `FAIL <имя> ...`. `NORECIPE` и `NOTAB` — справочные: предмет без рецепта или без вкладки, это не ошибка само по себе. `NOLANG` — нет перевода, это ошибка.

Перед новым прогоном `new` или `more` удали соответствующую папку из `run/saves`.

`MC112_NOPATCH=1` отключает все преобразования coremod. Используется для сравнения производительности с патчами и без.

## Проверка настоящего jar

Dev-запуск не доказывает работу в обфусцированной среде. Настоящий jar запускают так:

1. Создай отдельную игровую папку и положи в её `mods` собранный jar.
2. Возьми classpath из описания профиля `ForgeOptiFine 1.7.10` (файл json в `versions`), добавь jar этой версии, `-Djava.library.path` укажи на её `natives`.
3. Запусти `net.minecraft.launchwrapper.Launch` с `--tweakClass cpw.mods.fml.common.launcher.FMLTweaker`, `--gameDir` на эту папку и установленной переменной `MC112_AUDIT`.

С HBM нужна 64-битная Java 8 и `-Xmx2500M`: на 32-битной HBM падает с OutOfMemoryError при загрузке. Для старого мира копия сохранения кладётся в `saves/audit112`, а `-Dfml.queryResult=confirm` отвечает на вопрос о пропавших блоках.

Не запускай две копии игры или сборку одновременно.
